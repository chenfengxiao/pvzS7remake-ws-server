# S丐版 1.1 深度性能优化报告

## 一、结论

新版卡顿不是某一个植物或僵尸规则导致，而是以下几项运行时回退叠加：

- 全量图片启动预载；
- 永久逐帧等待图片的 RAF 轮询；
- 新增动画图集解码体积暴涨；
- 60 Hz 重复绘制 25 Hz 的相同逻辑状态；
- 高频数组复制、过滤和闭包分配；
- 包内混入大量不参与运行的构建/临时文件。

最主要的停顿来源是“大图同时解码 + 永不退出的图片轮询 + 重复绘制”。优化版已经把这三条链路从结构上移除，而不是用降低僵尸数量、关闭动画或删除机制的方式掩盖问题。

## 二、旧版与新版差异证据

### 1. 启动加载行为

最新版在 `wire()` 后执行：

```text
S7_SPRITES.preloadAll()
s7RedrawWhenReady() -> requestAnimationFrame(s7RedrawWhenReady)
```

Chromium 内存页对照：

| 项目 | 新版原包 | 优化版 |
|---|---:|---:|
| 注册精灵数 | 286 | 286 |
| 启动后图片实例 | 286 | 0 |
| 600 ms 内 `s7RedrawWhenReady` 调度 | 41 | 0 |
| 失败图片记录（无资源测试入口） | 286 | 0 |

注册表没有删减；优化版只是不再提前创建和解码尚未出现的贴图。

### 2. 动画解码内存

浏览器解码后的常见内存近似为 `宽 × 高 × 4`。最终僵尸动画注册表统计：

| 版本 | 文件数 | 磁盘大小 | 理论 RGBA 解码量 |
|---|---:|---:|---:|
| 旧版 S7 | 35 | 23.9 MiB | 194.1 MiB |
| 新版原包 | 39 | 27.4 MiB | 698.9 MiB |
| 优化版 | 39 | 29.2 MiB | 274.1 MiB |

优化版仍保留新版新增的 39 项动画资源，只降低过度分辨率。损失压缩率不是目标；运行时解码和 Canvas 采样成本才是目标。

原包最大资源包括：

- 气球走路：约 105.8 MiB；
- 雪橇行走/攻击/死亡：合计约 214.5 MiB；
- 矿工 6 套动作：合计约 246 MiB。

### 3. 重复绘制

游戏逻辑为 25 Hz。真实 Chromium 1.2 秒运行窗口：

| 项目 | 新版原包 | 优化版 |
|---|---:|---:|
| 逻辑帧 | 30 | 29 |
| `draw()` 次数 | 72 | 29 |

逻辑推进数量基本相同，绘制次数下降约 59.7%。优化没有跳过植物、僵尸、子弹或技能更新。

## 三、代码重构

### 1. 资源加载器

- `image(id)` 首次访问时才建立 `Image`。
- `setState()` 仅加载当前动画 clip 使用的图层。
- 图片加载/失败后合并为一次重绘。
- 保留 `preloadAll()` 作为显式诊断 API，但启动路径不再调用。
- `ready(id)` 保持原公共语义：显式查询会启动该单一资源加载。

### 2. 图集处理

以下 10 张图逐帧等比缩小 50%：

- `balloon_walk_new.webp`
- `bobsled_walk.webp`
- `bobsled_attack.webp`
- `bobsled_death.webp`
- `digger_underground.webp`
- `digger_surface.webp`
- `digger_stun.webp`
- `digger_walk.webp`
- `digger_attack.webp`
- `digger_death.webp`

共 250 帧。验证程序从原包逐帧裁切、按 LANCZOS 生成目标尺寸，再与优化资源解码像素比较，250/250 完全一致。

气球走路原图实际尺寸为 5145×5392，对应 1029×1348 的 5×4 网格，仅有 20 帧。原元数据写成 8 列、25 帧，属于读取几何错误；优化版修正为 5 列、20 帧。

### 3. 主循环与渲染

- 逻辑仍固定 0.04 秒。
- 有逻辑步时立即绘制。
- 没有逻辑变化时不重复画同一状态。
- 最长 120 ms 强制刷新一次，覆盖窗口状态或异步图片完成等情况。
- 异常保护路径强制清理并立即绘制错误提示。

### 4. 内存分配

- 统一 `compactArrayInPlace()`，不再每帧替换大数组。
- 完整性能清理每 8 个逻辑帧执行；超限或异常时立即执行。
- 植物同格分组数组复用。
- 热路径绘制不再为每株植物创建闭包。
- 动画快照从全局共享对象改为每个 runtime 独立对象，避免跨实体引用互相覆盖。
- 长关键帧轨道用二分查找；短轨道继续线性扫描。
- 动画事件直接遍历，不再先创建 `filter()` 结果数组。

微基准结果：

| 项目 | 新版原包 | 优化版 | 改善 |
|---|---:|---:|---:|
| 长轨道动画采样 | 10.7 ms | 9.8 ms | 约 1.09× |
| 高频实体清理 | 11.3 ms | 1.3 ms | 约 8.69× |

## 四、为什么没有丢功能

### 1. 核心机制代码未动

以下 12 个模块与本轮上传的最新版逐字节一致：

- `20_config_rules.js`
- `21_entity_registry.js`
- `30_state_geometry.js`
- `31_query_collision.js`
- `50_plant_simulation.js`
- `51_damage_combat.js`
- `60_zombie_simulation.js`
- `80_ui_quad.js`
- `90_s7_progression.js`
- `91_s7_elements_shooting.js`
- `92_s7_plant_actions.js`
- `93_s7_special_systems.js`

也就是说，植物动作、僵尸行为、伤害、元素、索敌、升级、盲盒、指令机制和 UI 操作没有通过“优化”被删改。

### 2. 注册表和动画清单未缩水

- 运行精灵注册数：286 → 286。
- 最终僵尸动画清单键数：39 → 39。
- 只删除了未引用备份、旧构建物和临时处理材料。

### 3. 浏览器回归

真实 Chromium 内存文档加载高性能入口，并通过路由读取发布包中的实际图片。以下均通过：

- 总体自检；
- 动画引擎自检；
- 植物种植与绘制；
- 僵尸受击透明反馈；
- 向日葵/逆时草照耀契约；
- 气球落地后向左行走与啃食；
- 仙人掌空中/地面双模式；
- 猫尾草空中气球优先；
- 猫尾炮塔 3 格/秒；
- 气球、雪橇、矿工优化图真实加载及几何校验。

页面错误、控制台错误、渲染错误均为 0。

## 五、发布结构

推荐入口：

```text
index.html
dist/S7_FAST_ENTRY.html
```

`S7_FAST_ENTRY.html` 内联代码、外置资源，约 0.9 MiB。它保留时间轴贴图和全部功能。

完整 Base64 单文件曾成功构建为约 139.3 MiB，并通过 349/349 内嵌资源哈希和 22 个脚本语法验证；但未放入最终 ZIP。原因是把上百 MiB Base64 放进 HTML DOM 会产生无法通过惰性图片解码完全消除的解析和内存成本。需要兼容单文件时可执行：

```bash
npm run release:single
```
