# S丐版 1.2 偶发卡顿根因诊断与修复报告

日期：2026-08-04

## 1. 结论

本轮确认的“关闭时间轴动画后仍会时不时卡一下”不是时间轴贴图是否被画到 Canvas 上这么简单，而是**视觉开关只关闭了最终绘制，后台时间轴、资源解码和周期性 DOM 重建仍在运行**。上传版在旧版绘制模式下仍会：

1. 每个 0.04 秒逻辑帧遍历全部植物与僵尸，解析动画状态并推进时间轴；
2. 为全部动画 runtime 采样根节点及图层姿态；
3. 首次进入动作时继续创建并解码对应精灵图；
4. 每 250ms 重建状态卡片和排名表的 `innerHTML`；
5. 每帧为每个实体重新测量、描边并填充简称文字；
6. 两张时间轴主题图片在旧版模式下也会启动加载。

因此，即使用户看到的是旧版 Emoji 绘制，主线程仍会遭遇随机动作切换带来的图片解码、动画对象分配、字体排版和 DOM/GC 峰值，表现为不固定间隔的顿挫。

## 2. 结构性修复

### 2.1 战斗事件时钟与视觉时间轴真正分离

旧版绘制模式不再为所有实体运行视觉时间轴。仅保留确实参与战斗规则的事件轨道：

- 报纸僵尸：破报、无敌过渡、暴走、啃食、掉头/掉手事件；
- 玉米投手：投射物生成与投掷完成事件。

其他植物和僵尸在旧版模式下不再解析 clip、不再采样姿态、不再创建视觉 runtime。切换回时间轴模式时，完整动画路径仍照常运行。

### 2.2 旧版模式彻底禁止时间轴资源解码

- `setState()` 仅在时间轴模式或显式诊断预载时调用 `preloadClip()`；
- 旧版事件时钟推进时不调用 `samplePose()`；
- 时间轴主题背景和阶数牌改为 getter 惰性加载；
- 特效精灵和报纸掉落部件在旧版模式使用轻量 Canvas 备用图形；
- 从时间轴切回旧版时，立即清除所有纯视觉 runtime，只保留报纸僵尸与待投掷玉米的事件 runtime；即使游戏正处于暂停状态也不会滞留；
- 释放精灵注册表和主题图片的 JS 引用，并主动中止尚未完成的图片请求/解码，避免切换后的尾部解码峰值。

### 2.3 UI 不再固定周期整块重建

- 时钟和按钮文字只在内容变化时更新；
- 状态卡片重建频率限制为最多 500ms 一次；
- 排名表重建频率限制为最多 1000ms 一次；
- 生成后的 HTML 与上次一致时不写入 DOM，避免无意义布局和垃圾回收。

### 2.4 实体简称改为有预算的静态图块缓存

上传版每帧对每个实体执行 `measureText + strokeText + fillText`。压力场景中仅 `fillText` 可超过每帧 400 次。本版将不变化的实体简称按“文字、颜色、格子尺寸、DPR”缓存为离屏 Canvas；为避免首帧一次生成几十个缓存导致新的长任务，每个逻辑帧最多新建 2 个，其余当帧沿用原绘制，随后逐步进入缓存路径。


## 3. 受控性能对照

最终版采用同一 Chromium 环境、1600×1000 视口、固定随机种子、旧版绘制模式、中等压力场景。为降低单次宿主负载波动，优化前后各运行 2 次、每次 6 秒，以下取中位数。

| 指标 | 上传基线 | 最终修复版 | 变化 |
|---|---:|---:|---:|
| 时间轴精灵 `Image` 实例 | 92 | 0 | 清零 |
| 动画 runtime | 88 | 6 | 仅保留事件关键对象 |
| 动画 Tick 平均 | 1.718 ms | 0.349 ms | -79.7% |
| 动画 Tick P95 | 4.300 ms | 0.950 ms | -77.9% |
| Update 平均 | 7.017 ms | 5.457 ms | -22.2% |
| Update P95 | 17.300 ms | 16.150 ms | -6.6% |
| Draw 平均 | 14.869 ms | 10.660 ms | -28.3% |
| Draw P95 | 44.800 ms | 50.800 ms | +13.4%（两次短测抖动） |
| UI 刷新平均 | 1.523 ms | 0.435 ms | -71.5% |
| Long Task 数量 | 48 | 21 | -56.2% |
| 6 秒内推进逻辑帧 | 139.5 | 143.5 | +2.9% |

Draw P95 在两次短测中受 Chromium 冷字体、JIT 和宿主调度影响仍有波动，因此未将其包装成“全面下降”。更稳定的验收证据是：旧版模式时间轴图片为 0、runtime 大幅下降、动画平均/P95 显著降低、Draw 平均下降、Long Task 数量减少一半以上，并且固定逻辑帧战斗结果完全一致。

### 3.1 最终独立浏览器复核

在完成所有代码回退与重新构建后，再以 70 个植物、80 个僵尸、固定种子、旧版绘制、6 秒墙钟独立复核：

| 指标 | 上传基线 | 最终修复版 | 变化 |
|---|---:|---:|---:|
| 时间轴精灵 `Image` 实例 | 61 | 0 | 清零 |
| 动画 runtime | 113 | 14 | 仅保留当前报纸/玉米事件对象 |
| 动画 Tick 平均 | 1.383 ms | 0.380 ms | -72.5% |
| 动画 Tick P95 | 3.300 ms | 0.900 ms | -72.7% |
| Update 平均 | 5.435 ms | 4.617 ms | -15.1% |
| Draw 平均 | 8.589 ms | 7.299 ms | -15.0% |
| UI 刷新平均 | 1.735 ms | 0.754 ms | -56.5% |
| 最大 RAF 间隔 | 333.4 ms | 250.0 ms | -25.0% |
| 页面/控制台错误 | 0 | 0 | 均无错误 |

短时间 Long Task 和单次最大值仍受 Chromium 冷启动及宿主调度影响，不作为唯一门槛；资源实例归零、动画时钟平均/P95、绘制平均值和模式切换释放结果均再次成立。机器可读结果见 `dist/stutter-independent-browser-verification.json`。

### 3.2 主体 Emoji 缓存方案已测试并撤回

中断前曾尝试把植物/僵尸主体 Emoji 也缓存为离屏 Canvas。最终使用同一份代码、相同 45 个植物与 80 个僵尸静态场景，交替运行 3 轮、每轮测量 250 次绘制：

- 保留浏览器原生 `fillText`：绘制均值中位数 5.481 ms，P95 中位数 12.100 ms；
- 启用 Emoji 离屏缓存：绘制均值中位数 5.724 ms，P95 中位数 12.400 ms；
- 均值反而上升约 4.4%，原因是 `fillText` 成本虽下降，但新增的大量 `drawImage` 和位图缩放抵消并超过收益。

因此最终版**没有保留这层缓存**，避免把一个未经证实的“补丁优化”继续叠在渲染链路上。实体简称缓存仍保留，因为其包含 `measureText + strokeText + fillText + 背景框`，复用收益明确。原始 A/B 记录见 `dist/rejected-emoji-glyph-cache-ab.json`。

## 4. 功能与回归验证

### 4.1 300 帧确定性战斗对照

在固定随机种子下，优化前后各手工推进 300 个逻辑帧，比较：

- 所有存活植物的 ID、类型、位置、血量、CD、年龄和玉米投掷状态；
- 所有存活僵尸的 ID、类型、位置、血量、防具、报纸暴走阶段与防御状态；
- 所有子弹的位置、寿命、伤害和目标；
- 队伍击杀、伤害、开盒数据；
- 报纸掉落部件和特效数量。

结果：**战斗快照逐项完全一致**。说明本次只剪除了视觉空转，没有改变规则时钟和伤害结果。

### 4.2 模式切换

- 时间轴模式可正常创建当前场景所需贴图；
- 切回旧版后精灵缓存立即变为 0；
- 暂停状态下切换也会立即清除纯视觉 runtime，独立场景中由 10 个降至 2 个必要报纸事件 runtime；
- 模式最终为 `legacy`；
- 页面错误和控制台错误均为 0。

### 4.3 自检

通过：Animation、B02A、B02B、B03C、B04A、B04B、B04C、S7Final。

B03A/B03B 在上传原包和修复包中结果相同，属于基线自检断言过期：B03A 仍硬编码 13 个默认 clip，但当前注册表已有 14 个；B03B 仍硬编码 5 个资源而当前为 6 个，并要求窝瓜 resolver 返回 impact，而当前基线 resolver 固定返回 idle。所有 B03A/B03B 列出的资源和 clip 均存在。本轮未借性能修复擅自改变窝瓜动画状态映射。
