S丐 v1.7.0｜2服/3服联机根因修复
日期：2026-08-16

一、3服“没进入却提示已进入3服”根因
根因不在 MQTT 房间状态，而在“同浏览器同服单实例锁”的返回值设计：
- 旧实现 acquire() 只返回 boolean。
- Web Locks API 异常、localStorage 不可写等“锁后端故障”也会返回 false。
- 入口层把所有 false 无条件翻译成：
  “你已经进入3服联机模式，不可继续进入”。
因此该提示可能是技术故障误报，并不代表真的存在另一个3服页面。

修复：
1. 锁模块新增 acquireDetailed()，明确区分：
   - acquired / already-owned：本页成功持有；
   - occupied：确实有其他页面占用；
   - backend-unavailable：锁后端不可用。
2. Web Locks 失败后依次退到 localStorage 租约、BroadcastChannel；全部不可用时仅进入兼容降级模式，不再误报“已进入”。
3. 只有 reason=occupied 时，才显示“你已经进入X服联机模式，不可继续进入”。
4. 进入大厅失败时立即释放刚取得的锁，避免半进入状态留下本页锁。
5. 保留原规则：同浏览器同服最多一个页面；不同服务器互不占用。

二、2服始终连不上根因
前端 v1.7.0 已默认把2服切换成“家庭反向 MQTT/WSS 隧道”，但家庭服务器启动链仍然只执行：
  HOST="::" PORT="8080" node server.js
而 server.js 明确要求 S7_HOME_TUNNEL=1 才会启动 home_mqtt_tunnel。
结果是：
- IPv6 WebSocket 8080 可以正常监听；
- Node、防火墙、IPv6 检查都可能正常；
- 但前端默认等待的反向 MQTT 隧道根本没有启动；
- 所以2服必然等不到 welcome，表现为“2服连不上”。

修复：
1. 2服_启动.command：加入 S7_HOME_TUNNEL=1。
2. 2服_安装自动守护.command：launchd EnvironmentVariables 加入 S7_HOME_TUNNEL=1。
3. 2服_重启.command：若已有旧 launchd 配置，直接按当前包重新生成并重载，顺便修复“旧 plist 仍指向旧版本目录”的问题。
4. 2服_启动.command：检测到 launchd 已运行时自动转入上述校准/重启流程，避免旧进程占用 8080 后新版本启动失败。
5. 2服_状态.command：不再只看 8080 是否监听，还会检查 health 中 homeTunnel.enabled / brokerConnected。

三、此前两次修复为何看起来无效
交付包中的 dist/S7_FAST_ENTRY.html 是 03:48 的旧构建，实际仍是 S丐版 1.6.1；
而源码后续修改一直到 14:06-14:09。
因此如果测试的是 FAST_ENTRY，会出现“源码已经改过，但运行结果完全没有变化”。

- 新的同服单实例锁修复。
